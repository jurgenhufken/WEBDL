## ⚠️ Uitdagingen / risico's

### Architectonisch
- **TypeScript open** — JSDoc + @ts-check nu de default. Mocht type-safety te dun voelen, optie om alsnog TS toe te voegen (build-step). Beslissing parkeerd, niet blokkerend.
- **Workers nog niet bestaand** — scheduler POSTt nu direct naar bestaande `/download`. Werkt prima maar betekent dat workers (yt-dlp / python-spawn / fetch) nog niet onder uniform interface zitten. Komt in stap 4.
- **Geen DB-persist** — jobs in-memory. Bij server-restart gaan ze verloren. Workaround: server is stabiel, restart-cycle laag. Echte fix komt later.
- **Eén Source = vipergirls** — claim "per-site config ~50 regels" nog niet getest met meerdere sites. Pas bewezen na heavyfetish + FFF gebouwd zijn.

### Praktisch
- **debug-toolbar.js blijft groot** (9415 regels) tot alle sites gemigreerd zijn. Voor nu coexistentie OK want user heeft features die nog niet in nieuwe stack zitten (K2S-batch, screenshot, recording).
- **Cloudflare-issues** voor sommige sites (xfree, alohatube) — server-side fetch werkt niet zonder cookies. Browser-fetch-fallback nog te bouwen (alleen indien nodig per site).
- **Wachtlijst groeit** — 4 nieuwe sites in deze sessie gevraagd. Discipline om niet impulsief toe te voegen tot stack klaar is.

### Lessen geleerd vandaag
- **Stop met reactief patchen** — vandaag eerst chaos, daarna ARCHITECTURE.md + plan. Vasthouden aan plan i.p.v. elke nieuwe klacht direct beantwoorden.
- **TWEE sporen vermijden** — debug-toolbar én site-engine en oude én nieuwe vipergirls flow tegelijk = pijn. Eén weg per host.
- **Live progress > silent background** — user moet ZIEN dat het werkt. /api/jobs/:id polling lost dit op voor nieuwe stack.
